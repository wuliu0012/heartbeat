# Heartbeat：独立同步式 AI 自动唤醒心跳系统

**原创：空气小狗老师**

> 正常聊天照常连接模型，只在前端额外挂一个心跳同步地址。心跳服务获得当前对话的快照后，独立判断何时主动联系用户。

本文说明私有原型的设计背景，不是公开版接口契约。公开版已增加可运行代码，将模型配置改为服务端托管、状态改为 SQLite 事务；请以仓库首页和代码为准。本文不包含私人前端源码或现网配置；所有示例均为虚构数据，不含真实域名、IP、凭据、聊天、角色设定或记忆。

## 1. 一句话理解

它不是让 AI 真正一直运行，而是让服务器定期检查：用户是否已经空闲了一段时间？如果是，就拿最近一次同步的当前对话询问模型：现在要主动说一句话，还是保持安静？

**普通聊天链路与心跳链路分开，心跳服务不承担普通聊天请求的转发。**

## 2. 与 Dylan Heartbeat 的区别

参考项目：[callie0313/dylan-heartbeat](https://github.com/callie0313/dylan-heartbeat)。以下仅比较其公开 README 描述的接入架构，核对日期为 2026-10-15，不代表逐行代码审计。

| 比较项 | Dylan Heartbeat 的公开架构 | 本方案 |
|---|---|---|
| 普通聊天链路 | 客户端连接 Gateway，再由 Gateway 转发至模型 | 前端仍使用原有模型接口；心跳服务不在普通聊天转发链路中 |
| 上下文来源 | Gateway 接收聊天请求并维护时间线 | 前端主动向单独的心跳同步地址发送当前对话快照 |
| 主动消息衔接 | 由 Gateway 维护并注入主动行为上下文 | 由独立待投递队列保存，前端拉取、落盘并确认后进入对话 |

因此，本方案不是把聊天的 API 地址换成一个心跳转发站，而是给原来的前端**额外挂一个专用心跳同步地址**。

### “不转发聊天”不等于“没有任何 HTTP 代理”

例如，部署时可以使用同域路径 `/heartbeat-api/`，由 Nginx 将这些心跳接口请求送到只监听本机的服务。这属于 HTTPS 接入层的反向代理，不是接管日常聊天的模型网关。

“直连模型”在这里指正常聊天不经过本心跳服务；原本选择的模型服务商是否另有代理，属于另外一层配置。

## 3. 两条链路

```text
普通聊天：
用户 → 前端原有聊天逻辑 → 已配置的模型 API → 前端显示与保存

心跳链路：
当前对话与选中版本
        ↓ 独立同步
HTTPS 心跳接口 → 服务端当前上下文快照
                        ↓ 定时检查空闲时间
                    独立调用模型
                    ├─ 保持安静 → 不推送
                    └─ 主动消息 → 待投递队列 ＋ 手机通知
                                         ↓
                              前端拉取 → 本地保存 → ACK
```

两条链路可以调用同一个模型，但它们是独立请求。心跳服务暂时不可用，不应阻断普通聊天。

## 4. 上下文如何跟随当前对话

### 前端是当前对话的来源

前端同步的是活动窗口，而不是把所有窗口混在一起。一次同步包括：

- `conversation_id`：当前对话标识。
- `revision`：同步修订号，用来拒绝迟到的旧请求。
- `history`：当前对话中用户和 AI 的可用文字上下文。
- `cfg`：心跳调用模型所需的必要配置。

若消息有重新生成、编辑等多个版本，同步前先通过类似 `selectedMessageContent(message)` 的函数取**当前选中版本**。其他版本可以继续留在浏览器中供用户切换，但不能同时交给心跳模型。

当前实现会在保存、换窗等操作后做约 300 毫秒防抖同步；网页可见时约每 30 秒进行一次同步与主动消息拉取。页面重新可见、网络恢复时也会尝试更新。

### 服务端只认最新快照

服务端拒绝不大于已接收修订号的请求，避免旧网络请求晚到后覆盖新上下文。

它还对“对话标识＋模型配置＋历史”计算指纹。相同内容重复同步时沿用当前 `generation`；内容变化或切换对话时，生成新的 `generation`，并使旧待投递状态失效。

三个标识分工如下：

| 标识 | 用途 |
|---|---|
| `conversation_id` | 判断消息属于哪个对话 |
| `revision` | 判断同步请求是否已经过期 |
| `generation` | 判断一次生成是否仍基于当前上下文 |

服务器无法自动读取用户浏览器。所谓“当前上下文”，准确地说，是**最近一次成功同步的活动对话快照**。未成功同步的编辑、新消息或换窗，服务端暂时不知道。

## 5. 自动唤醒如何触发

服务器上的常驻进程周期性检查时间，不依赖网页一直开着。

基本条件可以写成：

```text
参考时间 = max(最近互动时间, 最近一次心跳入队后的时间)
空闲时长 = 当前时间 - 参考时间

没有有效上下文或模型配置 → 跳过
空闲时长不足阈值       → 跳过
达到阈值               → 调用模型进行心跳自检
```

示例配置：

| 参数 | 示例值 |
|---|---|
| 时区 | Asia/Shanghai |
| 白天时段 | 10:00 至次日 00:00 |
| 白天空闲阈值 | 60 分钟 |
| 夜间空闲阈值 | 180 分钟 |
| 白天检查间隔 | 10 分钟 |
| 夜间检查间隔 | 120 分钟 |
| 模型上下文截取 | 最近 40 条有效记录 |

阈值与检查间隔不是同一件事：达到 60 分钟不意味着精确在第 60 分钟发通知，还要等下一次检查，以及模型决定是否发言。

实现细节：当前版本在上下文指纹变化时也会刷新互动参考时间。因此它不是只按最后一条用户消息的时间计时；换窗、编辑或上下文变化也可能推迟下一次心跳。空上下文不会触发生成。

## 6. 模型如何决定说话或保持安静

心跳调用复用必要的原有系统提示词和当前文字上下文，再加入一段专门的自检指令。模型要么输出一小段主动消息，要么返回沉默标记，例如 `<SILENCE/>`。

这些自检指令和触发用的虚拟消息不应被当作用户真实发言展示或保存。前端保存的是最终主动消息，而不是内部自检提示词。

生成前截取当前对话、当前 `generation`。生成结束后再核对一次：如果期间用户已经换窗或上下文已更新，就丢弃这次过期生成，不能发进新对话。

心跳仍然是一次模型 API 调用，可能产生费用；“模型选择沉默”不等于“本次调用免费”。它也不保证每次检查都主动发言。

## 7. 通知与网页消息如何衔接

每条主动消息带独立 `id`、`conversation_id` 和 `generation`。

服务端先保存主动消息，再尝试发送手机通知。前端之后从队列拉取属于当前对话和当前代次的消息，按消息 ID 去重。

可靠投递顺序是：

1. `pull` 只读取，不立即删除队列消息。
2. 前端核对对话和代次，合并到浏览器聊天记录。
3. 本地保存成功后才发送 `ack`。
4. 服务端确认对话、代次与消息 ID 后，从待投递队列移除已确认消息。

如果本地存储不足，不能先 ACK，否则刷新后可能丢失消息。若保存成功而 ACK 失败，下次再拉取时用消息 ID 去重，避免重复插入。

需要区分：**入队成功、手机通知成功、网页保存成功**是三个不同状态。当前版本中手机推送失败不会取消已入队消息，之后仍能由前端拉取；它不是手机推送可靠重试系统，也不能把入队时间等同于通知实际到达时间。

## 8. 专用接口

以下路径相对于 `/heartbeat-api/`：

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/sync` | 同步当前对话和必要模型配置，返回当前代次 |
| POST | `/touch` | 对匹配的当前对话刷新互动时间 |
| GET | `/pull` | 按对话与代次读取待投递消息，不自动消费 |
| POST | `/ack` | 确认已成功保存的消息 ID |
| GET | `/status` | 查看连接状态和数量，不返回聊天正文或模型密钥 |

`pull` 带上对话标识与代次；`touch`、`ack` 同样必须匹配当前上下文。未知对话或过期代次不能读取或确认另一个对话的消息。

## 9. 安全与错误处理

- 对外只开放 HTTPS 同域入口，后端仅监听回环地址；旧公开心跳入口停用。
- 心跳请求使用独立请求头携带服务 Token，不把 Token 放入 URL。
- 同步等写请求检查允许的 Origin；代理标记是接入层辅助，不是身份凭据，不能代替 Token。
- 禁止把模型 Key、服务 Token、推送设备凭据、完整聊天或私人提示词写入公开仓库和运行日志。
- 当前版本会把前端必要模型配置同步到服务器私有状态文件；这不代表模型 Key 只存在服务器。私有状态文件需要严格权限与受限备份，不能当成无敏感数据的缓存。
- 当前文件式实现使用跨进程锁、临时文件和原子替换。单文件替换不等于多个文件具有数据库事务级的一致性；更高要求应改用事务数据库。

前端应区分错误原因：

| 情况 | 行为 |
|---|---|
| Token 缺失、401 | 提示鉴权问题 |
| 403 | 提示来源或接入权限不符，不能直接断言 Key 无效 |
| 409 | 过期请求或代次冲突，静默忽略，后续用最新状态同步 |
| 无效数据、请求过大 | 提示数据问题，不无限重试 |
| 断网、超时、429、5xx | 有限退避重试，持续失败再提示网络问题；保留定期恢复机会 |

瞬时网络波动不应该每次都弹“Token 错误”。

## 10. 适用边界

- 当前是单用户、单活动上下文模型，不是多租户系统，也不是每个窗口同时各跑一套独立心跳。
- 浏览器关闭后，服务器仍可依据最后快照检查；但它不知道网页关闭后的未同步变化。
- 当前心跳同步与模型输入以文字为主，不等于把原聊天中的图片、音频和完整工具执行信息全部透传给心跳模型。
- 心跳系统不自动继承前端所有动态记忆注入；需要额外接入的记忆应明确设计，不能宣称已经拥有。
- 旧请求排序依赖客户端修订号。跨设备时钟偏差、多个标签页竞争活动上下文是扩展时需要进一步解决的问题。
- 手机通知的送达、通知点击后打开的浏览器，以及浏览器中可用的本地聊天记录，需要真机验证。
- 公开的只是脱敏原理文档；本文不承诺复制一段配置就能无修改接入任意聊天客户端。
